## Persistence, failure and retention

The nominated original EXT4 journal backing contains separate root-owned stores:
`configuration/<predecessor-import-result-sha>/session` and `.../effects`.
Actual `ObserveImportJournalsAsync` / `DebianImportJournalStorage.Verify` placement
checks precede authorization. Stores reserve the original preparation generation
once for this successor; changing an operation ID does not permit replay.
Prior import/session records stay immutable. A checkpoint is evidence preservation,
not rollback or retry authority.

Every step requires intent/reopen, fresh observations, bounded effect, root-only
flush, semantic/delta readback and result/reopen. Missing readback or persistence
never means target unchanged. An unresolved session cannot be retried or declared
torn down because its supervisor exited. Normal VM shutdown is a separate outcome.

independent read-only checkpoint of the successful import. The target is **not**
