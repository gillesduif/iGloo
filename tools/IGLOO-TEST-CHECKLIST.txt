===============================================================================
 iGloo - post-install validation
 Run these on the freshly installed Linux, then reboot back to Windows.
 Everything lands on the USB stick, so one reboot is enough.
===============================================================================

STEP 0 - find the USB stick (run this first, it sets $USB for the rest)
-------------------------------------------------------------------------------
USB=$(ls -d /run/media/$USER/* /media/$USER/* 2>/dev/null | head -1); echo "USB=$USB"

  Nothing printed? Plug the stick in, open its folder once in the file manager
  so it gets mounted, then run the line again.


===============================================================================
 STEP 1 - THE BIG DUMP  (one command, writes everything to the stick)
===============================================================================
sudo sh -c "{ echo '### KERNEL'; uname -a; cat /proc/cmdline; echo; echo '### GPU BINDING'; lspci -nnk | grep -A3 -Ei 'vga|3d|display'; echo; echo '### MODULES'; lsmod | grep -Ei 'nvidia|nouveau' || echo NONE; modinfo -n nvidia 2>&1; nvidia-smi 2>&1 | head -12; echo; echo '### RENDERER'; glxinfo -B 2>/dev/null | grep -iE 'opengl renderer|opengl vendor' || echo 'glxinfo missing'; echo; echo '### SECURE BOOT'; mokutil --sb-state 2>&1; echo; echo '### NVIDIA PACKAGES'; (dpkg -l | grep -i nvidia || rpm -qa | grep -i nvidia) 2>&1; echo; echo '### MODULE REJECTIONS'; journalctl -b | grep -iE 'nvidia|module verification|lockdown|taint' | tail -30; echo; echo '### BOOT ENTRIES'; efibootmgr -v; echo; echo '### DISKS'; lsblk -f; findmnt -no SOURCE,FSTYPE /; echo; echo '### GRUB / WINDOWS ENTRY'; grep -ci windows /boot/grub/grub.cfg /boot/grub2/grub.cfg 2>/dev/null; echo; echo '### IGLOO AGENT'; systemctl status igloo-first-boot.service --no-pager 2>&1 | head -15; ls -la /var/lib/igloo/ 2>&1; echo; echo '### WIFI'; nmcli -t -f NAME,TYPE connection show 2>&1; ls /etc/NetworkManager/system-connections/ 2>&1; echo; echo '### MIGRATED FILES'; ls ~/Documents ~/Downloads ~/Pictures 2>&1 | head -20; } > \"$USB/igloo-test-\$(date +%F-%H%M).txt\" 2>&1"


 STEP 2 - copy the iGloo logs themselves
-------------------------------------------------------------------------------
sudo cp -r /var/log/igloo "$USB/igloo-logs" 2>/dev/null; sudo cp /var/log/igloo-post.log "$USB/" 2>/dev/null; sync; echo DONE

  Wait for "DONE" before unplugging.


===============================================================================
 STEP 3 - THE FULL BUNDLE  (preferred: it collects far more than STEP 1)
===============================================================================
sudo bash "$USB/igloo-collect.sh"

  Installs itself as /usr/local/bin/igloo-logs, so every later run is just:

sudo igloo-logs

  Writes <stick>/igloo-logs-<host>-<timestamp>/ plus a .tar.gz. This is the one
  to send back - it includes the browser, display and credential evidence that
  STEP 1 does not gather. The manifest inside is redacted (password and Wi-Fi
  keys stripped); check redacted-manifest.json yourself before sharing.


===============================================================================
 THE THREE CHECKS WORTH READING ON SCREEN
===============================================================================

1) IS THE GPU ACTUALLY DRIVEN?   <-- the single most important one
-------------------------------------------------------------------------------
lspci -nnk | grep -A3 -Ei 'vga|3d'

  GOOD : "Kernel driver in use: nvidia"
  BAD  : "Kernel driver in use: nouveau"  -> proprietary/open driver not active
  BAD  : no "Kernel driver in use" line   -> nothing is driving the card

  Packages can be installed while NOTHING is bound to the card. That exact
  state is what looked like success all day and was not. This line is the truth.


2) HARDWARE OR SOFTWARE RENDERING?
-------------------------------------------------------------------------------
glxinfo -B | grep -i "OpenGL renderer"

  GOOD : mentions NVIDIA / GeForce RTX 5070
  BAD  : "llvmpipe"  -> software rendering; the desktop works but the GPU is idle

  Missing glxinfo?   Mint/Debian: sudo apt install -y mesa-utils
                     Fedora:      sudo dnf install -y glx-utils


3) DID THE BOOT-ORDER FIX HOLD?
-------------------------------------------------------------------------------
efibootmgr -v

  Look at the "BootOrder:" line and check iGloo's installer target is AHEAD of
  any other Linux entry (debian / ubuntu / fedora).
  This is the bug where picking Mint booted the Debian installer instead.


===============================================================================
 IF ROTATION / REFRESH RATE DID NOT APPLY
===============================================================================
The agent logs exactly which stage gave up. Run this first:

sudo grep -iE "display|monitor|output|pnp" /var/log/igloo/agent.log

  "No display layout in the manifest"        -> Windows captured nothing
  "No connected outputs with readable EDID"  -> Linux could not read the monitors
  "Monitor XXXX ... is not attached here"    -> the PnP ids did not match  <-- likely
  "does not advertise WxH"                   -> the mode check rejected it

Then capture both sides of the match, so the ids can be compared:

for c in /sys/class/drm/card*-*; do s=$(cat "$c/status" 2>/dev/null); [ "$s" = connected ] || continue; echo "== $(basename $c)"; xxd -p -l 32 "$c/edid"; done

python3 -c "import json;d=json.load(open('/var/lib/igloo/manifest.json'));print(d.get('displays'))"

cat ~/.config/monitors.xml 2>/dev/null || echo "no monitors.xml written"

  monitors.xml exists but nothing changed? Log out and back in - Muffin/Mutter
  only read it when a session starts.


===============================================================================
 IF BROWSER DATA DID NOT COME ACROSS
===============================================================================
FIRST - did the fixed agent actually ship? Nothing below means anything until
this answers 2 and 2. A published build carries whatever agent.py was on disk
when it was published, so this is the one line that separates "the fix is wrong"
from "the fix was not in that run".

grep -c normalise_gecko_profiles /opt/igloo/agent.py
grep -c _chromium_config_homes  /opt/igloo/agent.py

  2 and 2 -> the fix shipped; carry on reading.
  0       -> the payload predates it. Rebuild + publish, reinstall, stop here.


FIREFOX / ZEN - where did the profile end up?
-------------------------------------------------------------------------------
On Debian the agent installs Flathub Firefox (the distro only has ESR, which is
too old for a profile Windows 153 touched) and moves the profile into its
Flatpak home. Mint and Fedora ship release Firefox and keep the native path.

ls -d ~/.mozilla/firefox ~/.var/app/org.mozilla.firefox/.mozilla/firefox 2>/dev/null
flatpak list --app | grep -i firefox

  Exactly one of those two directories should hold the profile. Debian: expect
  the Flatpak one AND org.mozilla.firefox in the list. Mint/Fedora: expect the
  native one and NO Firefox flatpak.

grep -iE "firefox|profile is from" /var/log/igloo/agent.log

  Says which way it went and why, e.g. "Profile is from Firefox 153 but this
  distribution ships 140 - installing org.mozilla.firefox".

Then read profiles.ini in whichever directory won (FF=that path):

cat "$FF/profiles.ini"

  GOOD : Default=1 sits on the profile that holds the data, and there is NO
         [Install<HEX>] section left in the file.
  BAD  : an [Install...] section is still there -> the agent never rewrote it,
         and Firefox is falling back to whatever old profile has Default=1.

for d in "$FF"/Profiles/*/; do du -sh "$d"; done

  The profile carrying Default=1 must be the big one (hundreds of MB). If
  Default=1 points at a 1 KB stub, that is the whole bug.

ls "$FF"/Profiles/*/compatibility.ini

  Must say "No such file". A leftover one makes Firefox refuse the profile,
  because Windows ran a newer build than the ESR the distro ships.


BRAVE - where did the passwords land?
-------------------------------------------------------------------------------
flatpak list --app | grep -i brave
find ~/.var/app/*/config -maxdepth 5 -name "Login Data" -exec ls -la {} \;
ls -la ~/.config/BraveSoftware/Brave-Browser/Default/"Login Data"

  Login Data must exist under whichever form of Brave is installed. A Flatpak
  Brave never reads ~/.config, and a packaged Brave never reads ~/.var/app.

cat ~/.local/state/igloo-credentials.log

  "Imported N browser login(s)" -> done.
  No such file                  -> the login hook never ran.

ls -la ~/.local/share/igloo/credentials.json

  Still present -> the import has not completed: wrong password, or cancelled.
  It retries at the next login until the attempts run out.

BRAVE - did the rest of the profile come across?
-------------------------------------------------------------------------------
Bookmarks, history, favicons and cookies are NOT protected by the Windows master
key, so they are copied off the NTFS partition like any other file. Check the
profile that Brave actually reads (Flatpak Brave never uses ~/.config):

P=~/.var/app/com.brave.Browser/config/BraveSoftware/Brave-Browser/Default
ls -la "$P/Bookmarks" "$P/History" "$P/Favicons" "$P/Network/Cookies"
sqlite3 "$P/History" "select count(*) from urls"
sqlite3 "$P/Network/Cookies" "select count(*) from cookies"

  A History of a few hundred KB with a non-zero url count means it came across.
  An 8 KB file with 0 rows means Brave created a fresh one.

  Extensions and payment cards are NOT migrated. Extensions are signed against
  the machine; cards are left behind on purpose.


APPS THAT SHOULD HAVE BEEN INSTALLED
-------------------------------------------------------------------------------
flatpak list --app --columns=application

  Every browser you ticked under BROWSER PROFILES must appear here too, even if
  it was not ticked under SUGGESTED LINUX APPS - migrating a profile onto a
  machine without the browser is useless.


===============================================================================
 IF THE DRIVER DID NOT LOAD - the two lines that say why
===============================================================================
mokutil --sb-state
journalctl -b | grep -iE "module verification|lockdown|nvidia"

  "SecureBoot enabled" + a "module verification failed" / "Loading of unsigned
  module is rejected" line  ==  Secure Boot refused the module.
  Fix: turn Secure Boot off in firmware, or enrol a MOK and sign the module.

  The iGloo agent now writes this conclusion in plain words - worth checking:
sudo grep -iE "nvidia|secure boot|refused|module" /var/log/igloo/agent.log | tail -30
